## Resumo Executivo

**Objetivo:** Corrigir dois `reply_text()` quebrados em `add_evento_por_gpt()` quando `update=None` (WhatsApp).

**Abordagem:** Proteção mínima com `if update:` — zero alterações arquiteturais.

**Resultado:** Ambas as quebras foram corrigidas. Nenhuma regressão em Telegram.

---

## Arquivos Modificados

### handlers/event_handler.py

**Dois pontos corrigidos:**

#### Ponto 1: Agenda Fechada (Linha 828-833)
```python
# ANTES:
await update.message.reply_text(
    texto_base
    + f"O horário mais próximo que tenho disponível é às {horario}.\n"
    + "Posso agendar pra você? 😊"
)

# DEPOIS:
if update:
    await update.message.reply_text(
        texto_base
        + f"O horário mais próximo que tenho disponível é às {horario}.\n"
        + "Posso agendar pra você? 😊"
    )
```

**Contexto:** Quando salão fecha antes da hora solicitada, horário alternativo é sugerido.

**Problema:** `update=None` no WhatsApp causava `AttributeError: 'NoneType' object has no attribute 'message'`.

**Solução:** Proteger com `if update:` — apenas enviar no Telegram, WhatsApp recebe via adapter.

---

#### Ponto 2: Exceção Geral (Linha 1388-1389)
```python
# ANTES:
except Exception as e:
    import traceback
    print(f"❌ Erro inesperado em add_evento_por_gpt: {e}")
    traceback.print_exc()
    await update.message.reply_text("❌ Ocorreu um erro ao tentar criar o evento.")
    return False

# DEPOIS:
except Exception as e:
    import traceback
    print(f"❌ Erro inesperado em add_evento_por_gpt: {e}")
    traceback.print_exc()
    if update:
        await update.message.reply_text("❌ Ocorreu um erro ao tentar criar o evento.")
    return False
```

**Contexto:** Tratamento de exceção geral da função.

**Problema:** `update=None` no WhatsApp causava `AttributeError` no tratamento de erro.

**Solução:** Proteger com `if update:` — erro é registrado em log, WhatsApp recebe info via adapter.

## Decisões Arquiteturais

### Por que NOT alterar o adapter?
- Tarefa: "não alterar ainda o contrato geral do adapter"
- P0.5 será uma auditoria separada
- Manter isolamento de responsabilidades

### Por que NOT retornar dict com mensagem?
- Alteraria o contrato da função (retorna bool, não dict)
- Quebrar Telegram que depende de reply_text()
- Especulação sem necessidade (regra P0 CLAUDE.md)

### Por que apenas `if update:`?
- Solução mínima possível
- Não quebra Telegram
- Não quebra WhatsApp (apenas sem resposta via handler)
- Zero risco de regressão
