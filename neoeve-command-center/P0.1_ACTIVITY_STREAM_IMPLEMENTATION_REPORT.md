```python
# ETAPA 5: Project to Activity Stream (WebSocketEventLog)
# Non-fatal integration: failure here does not invalidate main projection
try:
    ws_log_service = WebSocketEventLogService()
    sequence = ws_log_service.log_event(
        db=self.db_session,
        event_id=event.event_id,
        event_type=event.event_type.value,
        tenant_id=tenant_id,
        project_id=project_id,
        payload=event.payload,  # Full payload for Activity Stream
    )

    if sequence:
        logger.debug(
            f"Event {event.event_id} logged to Activity Stream (sequence={sequence})"
        )
    else:
        logger.debug(
            f"Event {event.event_id} already in Activity Stream (idempotent)"
        )
except Exception as e:
    # Non-fatal: Activity Stream is optional, don't fail the main projection
    logger.warning(
        f"Failed to log event {event.event_id} to Activity Stream: {e} "
        f"(main projection still successful)"
    )

return True
```

## 2. DESIGN DECISIONS

### 2.1 Idempotência

**Estratégia:** Verificação no `WebSocketEventLogService.log_event()`
- Retorna `None` se evento já foi processado (duplicata)
- Usa `event_id` como chave única
- Não duplica em retry

### 2.2 Atomicidade

**Estratégia:** Mesma transação PostgreSQL
- `self.db_session` compartilhado entre AgentEvent e WebSocketEventLog
- Ambas commitadas juntas ou rollback juntas
- Garantia ACID nativa do PostgreSQL

### 2.3 Multi-tenant Isolation

**Estratégia:** Validação de tenant_id
- Usa `tenant_id` validado já extraído em `_extract_tenant_context()`
- Nenhuma aceitação de tenant_id do frontend
- Isolamento garantido através de `tenant_id` em índices

### 2.4 Non-Fatal Failure

**Estratégia:** Não interromper projeção principal
- Try-catch envolve apenas `log_event()`
- Falha gera warning, não exception
- AgentEvent é commitado mesmo se Activity Stream falhar
- ACK acontece normalmente (sucesso da projeção principal)

## 5. GARANTIAS

### ✅ Idempotência
- Mesmo evento processado 2x → Apenas 1 registro em WebSocketEventLog
- Verificado em `WebSocketEventLogService.log_event()` usando `event_id`

### ✅ Multi-tenant Isolation
- Eventos do tenant A não aparecem para tenant B
- Validação através de `tenant_id` em índices
- Teste: `test_websocket_log_multi_tenant_isolation`

### ✅ Atomicidade
- AgentEvent e WebSocketEventLog commitados juntos
- Falha em 1 → Rollback de ambas
- Ou sucesso em ambas na mesma transação

### ✅ Non-Fatal Failure
- Falha em Activity Stream → Apenas log warning
- AgentEvent é commitado normalmente
- ACK acontece (projeção bem-sucedida)
- Teste: `test_websocket_log_failure_does_not_break_projection`
