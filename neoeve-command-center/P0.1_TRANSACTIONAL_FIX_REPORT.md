## 1. CAUSA RAIZ

A implementação original violava atomicidade através de **duplos commits independentes**:

### Fluxo Errado (Rejeitado):

```
consume_and_project() INICIA transação
    ↓
_project_event(event)
    ├─ add(agent_event) + flush()
    ├─ log_event()
    │   ├─ add(websocket_event)
    │   └─ db.commit()  ← PRIMEIRO COMMIT (linha 81)
    │       └─ WebSocketEventLog permanente ISOLADAMENTE
    └─ return True
    ↓
consume_and_project() continua...
    └─ db.commit()  ← SEGUNDO COMMIT (linha 219)
        └─ AgentEvent permanente
```

**Problema:** Se exceção ocorrer entre commits:
- WebSocketEventLog JÁ foi commitado
- AgentEvent NÃO foi commitado
- Resultado: Inconsistência silenciosa

---

## 2. ARQUIVOS ALTERADOS

### A. `backend/app/services/websocket_event_log_service.py`

**Mudança Principal:** Remover `db.commit()`, usar `db.flush()` em vez

#### Antes (Rejeitado):
```python
def log_event(...):
    event = WebSocketEventLog(...)
    db.add(event)
    db.commit()  # ← Commit independente
    return event.sequence
```

#### Depois (Correção):
```python
def log_event(...):
    # 1. Check if already exists (idempotency)
    existing = db.query(WebSocketEventLog).filter_by(event_id=event_id).first()
    if existing:
        return existing.sequence
    
    # 2. Add event
    event = WebSocketEventLog(...)
    db.add(event)
    db.flush()  # ← Validate constraints, don't commit
    # Let caller control transaction boundary
    return event.sequence
```

**Benefício:** 
- ✅ Sem commit independente
- ✅ Exception não capturada localmente (propaga para caller)
- ✅ Idempotência verificada explicitamente em código
- ✅ Caller controla transação completa

### B. `backend/workers/projection_worker.py`

**Mudança Principal:** Remover try-catch que capturava como non-fatal, propagar exception

#### Antes (Rejeitado):
```python
try:
    ws_log_service.log_event(...)
except Exception as e:
    logger.warning(f"Failed... (main projection still successful)")
    # Non-fatal

return True
```

#### Depois (Correção):
```python
# ATOMIC TRANSACTION: Both projections must succeed together
ws_log_service.log_event(...)  # ← Exception propagates if fails
# No try-catch — let caller handle transaction state

return True
```

**Benefício:**
- ✅ Falha em WebSocketEventLog propaga ao consume_and_project()
- ✅ Trigger rollback de ambas AgentEvent + WebSocketEventLog
- ✅ Atomicidade garantida
- ✅ Sem "non-fatal" falso

## 3. CONTRATO TRANSACIONAL

### Antes (Rejeitado):

```
BEGIN transaction A (checkpoint)
    commit()  ← Checkpoint status PROCESSING

BEGIN transaction B (implicit, no commit)
    add AgentEvent
    flush() AgentEvent
    
    BEGIN transaction C (inside log_event)
        add WebSocketEventLog
        commit()  ← COMMIT C
    
    return True

END transaction B (never started)

BEGIN transaction D (implicit, no commit)
    update checkpoint status IDLE
    commit()  ← COMMIT D
```

**Problema:** 3 commits separados para 1 evento

### Depois (Correção):

```
BEGIN transaction (single, explicit)
    add(checkpoint) → update status PROCESSING
    flush() checkpoint
    
    for each event:
        add(AgentEvent)
        flush() AgentEvent
        
        add(WebSocketEventLog)
        flush() WebSocketEventLog
        
        add(ProcessedEvent)
        flush() ProcessedEvent
    
    update(checkpoint) → status IDLE
    flush() checkpoint
    
COMMIT ÚNICO ← All projections persist atomically or rollback together
```

**Benefício:** 1 único commit para N eventos, atomicidade garantida

## 4. IDEMPOTÊNCIA

### Estratégia:

1. **Verificação Explícita em Código:**
   ```python
   existing = db.query(WebSocketEventLog).filter_by(event_id=event_id).first()
   if existing:
       return existing.sequence  # Idempotent
   ```

2. **UNIQUE Constraint como Proteção:**
   - `event_id` tem `unique=True` em model
   - Se reprocessamento ocorre simultaneamente, primeira inserção vence
   - Segunda inserção falha com IntegrityError

3. **Comportamento em Retry:**
   ```
   Primeira tentativa:
   - INSERT bem-sucedido → sequence retornado
   - Projections commitadas
   
   Retry (mesmo event_id):
   - Query retorna existing record
   - Return sequence (sem re-inserir)
   - Resultado: idempotente ✅
   ```

### Validação:

- ✅ `test_atomicity_idempotent_no_duplicates` valida retry sem duplicação
- ✅ UNIQUE constraint existe em model
- ✅ Idempotência é verdadeira (mesmo event_id = mesmo resultado)
